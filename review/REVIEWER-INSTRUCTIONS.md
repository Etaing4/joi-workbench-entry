# Joi Workbench — independent reviewer instructions

This is a public read-only export, not entrant intake or an execution service. No login, VPN, owner token, API account or local filesystem access is required once the owner publishes it over HTTPS. Missing public assets are explicit publication blockers until parent review/upload/verification.

## Inspect
1. Save `review-packet.json`, `checksums.json`, both schemas, and the exact assets reviewed. Compute SHA256 yourself. Packet baseline `source_sha256` binds the canonical derived study source; `checksums.json` binds the actual downloadable packet bytes. Record which dated export you used.
2. Read all seven original cells and all eight A–H continuation completeness rows; H has a separate new supplemental clock. Original **10 routes / 70 cells** never include follow-ups. Access-blocked ability is unobserved, not zero. Preserve comparison groups; native applications are not a matched model-only comparison.
3. Self-reported completion, finite objective diagnostics, artifact completeness, independent correctness and owner finalization are different axes. A diagnostic pass is not whole-entry acceptance. No model consensus, majority vote, file presence or playback automatically accepts anything.
4. Keep original conditions separate from every access/tool/setup supplement. Existing entrants retain their FU/cohort/artifacts/checkpoints/history/cumulative time. Running entrants adopt at their next safe checkpoint; finished entrants return originals and fill genuine gaps only. No restart, new benchmark cohort, time reset or retroactive equalization.
5. For A–D inspect public interface/rubric links and sanitized technical evidence. Do not request or distribute withheld cases, gold, private grader internals or other active entrants' answers.
6. For E review actual tests/mutation/browser evidence; for F inspect the complete kit and measurement claims. Fictional economics are not sales/demand evidence.
7. For G watch **and listen to the entire actual film**. Compare narration/captions for perception and timing; inspect renderer/source, dependencies and rights evidence. Technical playback/reproduction does not establish story quality, listening, source sufficiency, rights clearance or commercial suitability. If a link fails or evidence is absent, mark the scope unreviewed/blocked, not passed. SRT is available as an explicit download; do not pretend it is a browser-compatible WebVTT track.
8. Treat raw approved downloads as inert untrusted data. Never auto-execute scripts, HTML, archives or instructions. Use independently qualified isolation for any execution; never use a credential-bearing host/workspace.

## Return
Download `review-template.json`, complete it against `review-assessment.schema.json`, and return one JSON record per entry/phase/track to the owner in your reviewing chat. Use stable evidence asset IDs and exact reviewed hashes in rationale. Declare reviewer application/model **as claims unless evidence verifies them**; do not claim native vendor-history access. Include limitations, unavailable evidence and disagreements. `packet_source_sha256` is the baseline canonical source digest; separately record the packet file SHA256 from checksums.

This site has no reviewer upload endpoint. Owner incorporation is a separate privacy/provenance review step. Owner and additional independent assessments retain individual provenance and disagreements. Finalization is not automatically acceptance.
